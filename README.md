# سامانه منابع انسانی (HR)

برنامه دسکتاپ WPF برای مدیریت کارکنان و دپارتمان‌ها، با عملیات کامل CRUD، چارت سازمانی، مرخصی، ارزیابی‌ها و داشبورد.

| بخش | توضیح |
|---|---|
| `HR/` | رابط کاربری WPF (net10.0-windows) |
| `HR.Core/` | موجودیت‌ها، `PersonnelDbContext` (EF Core + SQL Server) و سرویس‌ها |
| `HR.Tests/` | تست‌های xUnit (بخشی بدون دیتابیس، بخشی نیازمند SQL Server) |
| `HR/DB/` | اسکریپت‌های SQL |

## پیش‌نیازها

- ویندوز، به‌همراه **.NET 10 SDK**
- **SQL Server** (اسکریپت مرجع با سطح سازگاری ۱۶۰ یعنی SQL Server 2022 ساخته شده؛ از نوع `hierarchyid` استفاده می‌شود)

## راه‌اندازی پایگاه داده

اسکریپت مرجع **`HR/DB/LastPersonnel.sql`** است.

- **پایگاه تازه:** کل فایل را اجرا کنید. توجه: دستور `CREATE DATABASE` داخل فایل مسیر فایل‌های داده را روی
  `C:\Program Files\Microsoft SQL Server\MSSQL16.MSSQLSERVER\...` ثابت کرده است. یا این مسیرها را با سرور خودتان
  هماهنگ کنید، یا پایگاه `Personnel` را خودتان بسازید و بقیه‌ی فایل را بدون بلوک‌های `CREATE DATABASE` / `ALTER DATABASE` اجرا کنید
  (فیکسچر تست‌ها هم همین کار را می‌کند).
- **پایگاه موجود:** فقط بلوک `UPGRADE EXISTING` در انتهای فایل را اجرا کنید.
- **داده‌ی تست:** بعد از ساخت پایگاه، فایل **`HR/DB/SeedLookups_Test.sql`** را اجرا کنید. این فایل جدول‌های `GeoType` و `Geo`
  (ایران با ۳۱ استان و ۲۰۵ شهر، و ۳۷ کشور دیگر) و فهرست نرم‌افزارهای رایج را پر می‌کند. بقیه‌ی lookupها (جنسیت، بانک، مدرک،
  سطح مهارت، نوع فایل و ...) از قبل در بخش `SEED LOOKUPS` خود `LastPersonnel.sql` پر می‌شوند. اگر `Geo` از قبل داده داشته باشد، اسکریپت به آن دست نمی‌زند.
- **معافیت نظام‌وظیفه:** برای فهرست کامل‌تر نوع و علت معافیت، `HR/DB/SeedExemptions.sql` را هم اجرا کنید (اختیاری، بعد از `LastPersonnel.sql`).
- فایل `Personnel-v2.sql` با مدل برنامه ناسازگار است و **نباید اجرا شود**. سه اسکریپت دیگر (`Brief_Schema_Updates.sql`،
  `Department_Enhance.sql`، `RelatedPerson_Phone_Address.sql`) منسوخ‌اند و محتوایشان در بلوک ارتقای فایل مرجع هست.

## تنظیمات

**رشته اتصال** (به ترتیب اولویت):

1. متغیر محیطی `PERSONNEL_CONNECTION`
2. `ConnectionStrings:Personnel` در `HR/appsettings.json`
3. پیش‌فرض: `Server=localhost;Database=Personnel;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true`

> پیش‌فرض به **instance پیش‌فرض SQL Server روی همین ماشین** (`localhost`) با Windows Authentication وصل می‌شود.
> برای instance نام‌دار از `Server=localhost\\NAME` و برای SQL Authentication از `User Id=...;Password=...` (به‌جای `Trusted_Connection`) استفاده کنید.

**مسیر ذخیره فایل‌ها** (عکس پرسنلی، مدارک، لوگوی دپارتمان) به ترتیب اولویت:

1. متغیر محیطی `HR_FILE_STORAGE`
2. `FileStorage:RootPath` در `HR/appsettings.json`
3. پیش‌فرض: `%ProgramData%\HRSuite\files`

## اجرا

```powershell
dotnet run --project HR
```

در اولین اجرا، چون هنوز کاربری وجود ندارد، پنجره ورود از شما می‌خواهد **مدیر اولیه** را بسازید (حداقل ۸ نویسه برای رمز).

### نقش‌ها

| نقش | دسترسی |
|---|---|
| مدیر (`Admin`) | همه‌چیز، از جمله مدیریت کاربران |
| منابع انسانی (`HR`) | ثبت، ویرایش، حذف و بازگردانی کارکنان و دپارتمان‌ها، ثبت مرخصی |
| بیننده (`Viewer`) | فقط مشاهده |

## عملیات CRUD

- **کارمند:** ثبت، ویرایش (همه بخش‌های پرونده)، حذف نرم، بازگردانی از «حذف‌شده‌ها»، حذف دائمی.
  کد ملی و کد پرسنلی یکتا هستند و شامل کارکنان حذف‌شده هم می‌شوند.
- **دپارتمان:** ثبت، ویرایش (والد، مدیر/جانشین/تنخواه‌دار، دفاتر، لوگو، بودجه)، حذف.
  حذف دپارتمان فقط وقتی ممکن است که زیرمجموعه و کارمند (حتی حذف‌شده) نداشته باشد.

## تست

```powershell
dotnet test
```

تست‌های بدون دیتابیس (مثل `EmployeeValidatorTests`) همیشه اجرا می‌شوند. تست‌های دیتابیس فقط وقتی اجرا می‌شوند که متغیر
`HR_TEST_SQL` (رشته اتصال به یک سرور SQL) تنظیم باشد، وگرنه رد می‌شوند.

> ⚠️ **هشدار:** فیکسچر تست پایگاه `Personnel` همان سرور را **حذف (DROP) و دوباره می‌سازد**.
> `HR_TEST_SQL` را هرگز به سروری که داده واقعی دارد اشاره ندهید.

چک‌لیست تست دستی (دود) در `HR/docs/smoke-test.md` است.
